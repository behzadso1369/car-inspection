کارهای بک‌اند .NET — api.carmacheck.com

۱۹ آبان ۱۴۰۵ · این فهرست فقط کار تیم API / CMS است. اصلاحات صفحه، لینک، sitemap و رندر HTML در ریپوی Next انجام شده یا می‌شود. لطفاً endpoint جدید نسازید مگر در همین سند آمده باشد.

محدوده: هاست api.carmacheck.com، CMS بلاگ، فایل تصویر، و فیلدهای Site/GetMasterPageData. ریدایرکت http/www، HSTS و ۴۰۴ دامنهٔ carmacheck.com کار IIS جلوی Next است، نه این API.
Next دیگر از همین endpointهای موجود می‌خواند. اگر داده خالی، رمز ناسازگار، ۵۰۰ یا تاریخ نامعتبر برگردد، صفحهٔ فرانت خراب یا ناقص می‌ماند. نیازی به endpoint تازه برای لیست بلاگ یا قیمت صفر نیست.

اولویت ۱ — محتوا و فایل خراب

۱جای‌خالی قالب داخل مقالهٔ منتشرشده

در HTML بعضی پست‌ها هنوز توکن‌هایی مثل {{SECTION_IMAGE_5_URL}} و {{DATE_PUBLISHED_FA}} مانده. این رشته‌ها در سایت زنده دیده می‌شوند و آدرس تصویر ساختگی پاسخ ۵۰۰ می‌دهد.

  • منبع: SiteBlog/SearchPostWithId فیلد Content / تصویر / تاریخ
  • قبل از Publish، همهٔ {{...}} باید جایگزین شده باشند؛ در غیر این صورت پست draft بماند
  • تصویر بخش باید فایل واقعی روی API باشد، نه placeholder

پذیرش: GET جزئیات همان پست‌ها هیچ {{ ندارد؛ URL تصویر ۲۰۰ و از نوع تصویر است.

۱لینک داخل متن به مقالهٔ ناموجود

در مقالهٔ تشخیص شاسی تصادفی، لینک «رنگ‌شدگی با گوشی» به نشانی‌ای می‌رود که امروز ۵۰۰/ناموجود است.

  • یا پست مقصد را منتشر کنید و canonical پایدار بدهید
  • یا لینک داخل Content را به slug واقعی همان مطلب اصلاح کنید
  • پست حذف‌شده را با ۵۰۰ برنگردانید: پاسخ خالی/۴۰۴ برای id نامعتبر کافی است تا Next بتواند ۴۰۴ واقعی بدهد

پذیرش: GET SiteBlog/SearchPostWithId?id=... برای id نامعتبر ۵۰۰ ندهد. لینک‌های داخل Content به پست ۲۰۰ با canonical درست برسند.

اولویت ۲ — دادهٔ عمومی که Next سروری می‌خواند

۲قیمت صفر — Site/CarNewPrice/Select

صفحهٔ /car-new-price حالا جدول را از سرور Next می‌سازد. داده هنوز از همین API رمزشده می‌آید.

  • قیمت صفر/منفی یا ردیف جعلی برنگردانید؛ اگر منبع قطع است isSuccess=false یا لیست خالی با پیام روشن
  • واحد پول (ریال/تومان) در قرارداد پاسخ یک‌بار و ثابت باشد
  • اگر تاریخ به‌روزرسانی واقعی دارید، در payload بگذارید (مثلاً updatedAtISO با timezone). فرانت دیگر «امروز» تقویم را به‌جای تازگی داده نشان نمی‌دهد
  • ۴۲۹ پشت‌سرهم برای SSR صفحه را خالی می‌کند؛ سقف معقول برای خزش سرور Next در نظر بگیرید

پذیرش: Select با pageSize حدود ۱۰۰۰، JSON معتبر، decryptپذیر، بدون ردیف قیمت صفر ساختگی.

۲بلاگ — نویسنده، تاریخ، lastmod

نقشهٔ سایت و schema مقاله از همین فیلدها پر می‌شود:

فیلدانتظار
AuthorName / CreatedByنام شخص واقعی با رضایت، یا خالی/سازمان. «تیم کارماچک» را به‌عنوان Person نفرستید
CreatedOn / CreatedDateISO با timezone (مثلاً +03:30 یا Z). بدون منطقهٔ زمانی ساعت مبهم است
ModifiedDateفقط بعد از ویرایش واقعی محتوا عوض شود؛ زمان build/خزش نباشد
BlogPostCanonicalیک slug پایدار /blog/... غیرعددی؛ id عددی فقط سازگاری قدیمی
ImagePathفایل موجود روی همین هاست؛ PNG چندمگابایتی را فشرده کنید

Endpointها: SiteBlog/SearchWithTerms · SiteBlog/SearchPostWithId · SiteBlog/GetRelatedPosts

پذیرش: لیست منتشرشده‌ها با take=1000 کامل است؛ RelatedPosts JSON ناقص برای Take=5 ندهد (قبلاً بعضی پست‌ها خراب می‌شدند).

۲تماس و ساعت کاری دو نسخه دارند

Site/GetMasterPageData → MasterSiteData

  • PhoneNumbers با NavbarPhoneNumber یکی باشند (الان ۰۲۱۹۱۰۹۰۲۸۳ در برابر ۰۲۱۹۱۰۰۱۷۴۰ دیده شده)
  • WorkingHours با ساعتی که در دادهٔ کسب‌وکار/نقشه می‌آید یکی باشد (۱۸ در برابر ۲۰)
  • آدرس کامل و یکسان

این فیلدها در فوتر، هدر و صفحهٔ تماس Next خوانده می‌شوند. اختلاف یعنی مشتری دو شماره/دو ساعت می‌بیند.

۲قوانین — Site/GetRegulationsData

  • تاریخ 10/05/1045 نامعتبر است؛ تاریخ واقعی شمسی/ISO با timezone بدهید یا فیلد را خالی بگذارید
  • متن هر ۲۲ بند در Content کامل باشد (فرانت دیگر متن را بعد از کلیک fetch نمی‌کند؛ همان HTML اولیه را نشان می‌دهد)
  • ضمانت/لغو/اعتراض را بدون تأیید حقوقی عوض نکنید؛ فقط تاریخ و توکن خراب را درست کنید

۲FAQ — Site/GetFAQ_CategoryData و GetFAQWithCategoryId

  • هر آیتم Question و Answer پر باشد؛ پاسخ خالی در HTML اولیه هم خالی می‌ماند
  • دسته‌بندی بدون سؤال برنگردانید یا صریح خالی باشد

۲دربارهٔ ما — Site/GetAboutUsPageData

این endpoint در API تعریف شده ولی فرانت هنوز از آن استفاده نمی‌کند. اگر قرار است بیوگرافی و مدرک از CMS بیاید:

  • برای هر فرد: نام، نقش واقعی، حوزهٔ تخصص، لینک مدرک مجاز و موجود
  • مدرک یا آمار ساختگی نگذارید؛ نبود مدرک = فیلد خالی
  • نمونه گزارش فقط اگر پالایش‌شده و قابل انتشار عمومی است

تا وقتی این داده تأیید نشده، Next همان دو معرفی فعلی را نشان می‌دهد. لازم نیست فرانت را به API ناقص وصل کنیم.

اولویت ۳ — فایل و هاست API

۳تصویرهای سنگین روی api.carmacheck.com

نمونه: تیگو ۸ حدود ۲ مگابایت، ال۹۰ حدود ۱٫۷ مگابایت. Next می‌تواند نسخهٔ بهینه بسازد، ولی منبع اصلی را هم فشرده کنید (WebP/JPEG معقول، عرض کافی موبایل).

فایل‌های ImagePath بلاگ و اسلایدر هم همین هاست‌اند.

۳robots زیردامنهٔ API

robots دامنهٔ اصلی carmacheck.com ربات‌های api.carmacheck.com را کنترل نمی‌کند. اگر مسیر مدیریتی/خصوصی روی API ایندکس‌پذیر است، robots یا هدر X-Robots-Tag همان هاست را جدا تنظیم کنید. فایل‌های تصویر عمومی موردنیاز رندر را نبندید.

۳پاسخ خطا برای id نامعتبر

برای پست/قیمت/FAQ ناموجود: ۴۰۴ یا isSuccess=false با بدنهٔ خالی، نه ۵۰۰. Next نبود قطعی رکورد را ۴۰۴ می‌کند؛ ۵۰۰ API را خطای سرور نگه می‌دارد و نباید به ۴۰۴ تبدیل شود.

چیزهایی که کار شما نیست

  • فوتر، robots.txt دامنهٔ اصلی، sitemap.xml، title/OG، H1
  • ریدایرکت http → https و www → بدون www (IIS جلوی Next)
  • HSTS و custom error IIS
  • ثبت نقشه در Search Console

چک‌لیست کوتاه برای تحویل

  • □ هیچ پست منتشرشده‌ای توکن {{...}} ندارد
  • □ لینک «رنگ‌شدگی با گوشی» به URL ۲۰۰ می‌رسد
  • □ SearchPostWithId برای id نامعتبر ۵۰۰ نمی‌دهد
  • □ CarNewPrice/Select بدون قیمت جعلی و با قرارداد واحد مشخص است
  • □ PhoneNumbers و NavbarPhoneNumber و WorkingHours یک نسخه‌اند
  • □ تاریخ قوانین معتبر است
  • □ FAQها Answer خالی ندارند
  • □ تصاویر شاخص بلاگ و مدل‌ها حجم معقول دارند

منبع: ممیزی سایت و Search Console ۱۹ آبان ۱۴۰۵. این فایل را به تیم API بدهید؛ نیاز به دسترسی پنل Next نیست.
