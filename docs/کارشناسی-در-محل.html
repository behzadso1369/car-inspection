راهنمای پیاده‌سازی «کارشناسی در محل»

مستند فارسی برای تیم — فلو کامل از رزرو تا گزارش بدنه (سناریو نمونه: سمند سفید)

۱. نمای کلی

کارشناسی در محل یعنی مشتری آدرس خود را ثبت می‌کند، پرداخت می‌کند، ادمین کارشناس اعزام می‌کند، کارشناس به محل می‌رود و گزارش بدنه ثبت می‌کند و مشتری گزارش را می‌بیند.

  1. آماده‌سازی ادمین (کارشناس + پوشش جغرافیایی)
  2. ورود مشتری (OTP)
  3. ثبت آدرس مشتری
  4. ساخت سفارش و حرکت فلو تا پرداخت
  5. پرداخت → وضعیت PendingAssignment
  6. ادمین: پیشنهاد و تخصیص کارشناس
  7. کارشناس: پذیرش و وضعیت میدانی
  8. ثبت چک‌لیست + گزارش بدنه
  9. مشتری: پیگیری اعزام + مشاهده گزارش

۲. مسیرهای فرانت‌اند (Next.js)

نقشمسیرتوضیح

۴. سناریو تست (سمند سفید)

  • مشتری: رضا احمدی — 09121234567
  • کارشناس: علی محمدی — 09120000000 (ExpertId=5)
  • آدرس: تهران، ولیعصر، پلاک ۱۲ — AddressId=45
  • پلاک: 124 ص 12 ایران 11 — شاسی: 147874
  • نتیجه: گلگیر جلو راست رنگ‌شده (Painted)
API پایه: https://api.carmacheck.com/api/
توکن‌ها: token (مشتری)، adminToken (ادمین)، expertToken (کارشناس) در localStorage

۵. APIهای مهم

مشتری

  • POST User/CreateUserAddress — ثبت آدرس و دریافت AddressId
  • POST OrderSite/Move/Private با addressId برای کارشناسی در محل (Id=1)
  • GET User/GetOrderExpertStatus?OrderId=
  • GET User/GetOrderBodyReport?OrderId=

ادمین

  • GET admin/OrderExpertAssignment/UnassignedOnSiteOrders
  • GET admin/OrderExpertAssignment/SuggestExperts?orderId=
  • POST admin/OrderExpertAssignment/AssignExpert

کارشناس

  • POST Expert/Accept
  • POST Expert/UpdateStatus — EnRoute → Arrived → InProgress
  • POST Expert/SubmitBodyReport

۶. وضعیت‌های زون بدنه

  • Ok — سالم (سبز)
  • Painted — رنگ‌شده (نارنجی)
  • Damaged — آسیب‌دیده (قرمز)
  • Replaced — تعویض‌شده (بنفش)
  • NotChecked — بررسی‌نشده (خاکستری)

۷. پیش‌نیاز بک‌اند

فرانت آماده است؛ برای کارکرد کامل، API باید:

  • نوع محل کارشناسی با IsOnSite=true در GetCarInspectionLocationData برگرداند
  • پس از پرداخت موفق، رکورد PendingAssignment بسازد
  • endpointهای admin و expert مطابق مستند API فعال باشند
